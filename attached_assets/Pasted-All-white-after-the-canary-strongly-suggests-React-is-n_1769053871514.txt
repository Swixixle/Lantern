All white after the canary strongly suggests **React is not mounting or the JS bundle is not executing**, not an in-app routing/component problem.

Here is the fastest, deterministic way to localize it.

## 1) Confirm whether the page is loading any JS at all (30 seconds)

On your laptop (preferred), open the preview in a new tab.

### A. Open DevTools → Console

* If you see **any red error**, paste the **first** one (topmost).
* If console is empty, continue.

### B. DevTools → Network

1. Check “Disable cache”.
2. Hard refresh: **Ctrl+Shift+R** (Windows) / **Cmd+Shift+R** (Mac).
3. In Network, filter by **JS** and look for:

   * any request in **red**
   * status **404 / 500**
   * “Failed to load module script”
4. Tell me the first failing request’s **status code** and **URL path**.

If you can only give one thing: **the first red Network entry**.

## 2) One-line “mount point” sanity check (common silent white screen)

In `client/index.html` (or whichever index Vite is using), verify you have:

```html
<div id="root"></div>
```

In `client/src/main.tsx` (or `main.jsx`), verify:

```ts
createRoot(document.getElementById("root")!).render(<App />);
```

If `id` differs (e.g., `app` vs `root`), you’ll get a white screen with no obvious clue.

## 3) Most likely cause in your situation

You already had a **TypeScript compile error** earlier in `client/src/pages/lantern-extract.tsx` (TimelineItem fields mismatch). If that error is still present (or another compile error exists), Vite will often show an overlay—but sometimes the overlay is blocked or not injected, producing a plain white screen.

So the quickest check:

### Run this in the shell:

```bash

```

and watch the terminal. If there’s a compile error, it will print there even if the overlay doesn’t show.

If you see errors, paste the first one.
