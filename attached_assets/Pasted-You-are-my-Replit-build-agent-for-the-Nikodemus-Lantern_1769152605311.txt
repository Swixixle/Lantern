	2.	Photos / Camera: capture photo from device camera.
	3.	Scan: multi-page capture workflow; produce either a multi-page PDF or ordered page images.

Backend/API Requirements (Case-bound routing)

Implement/confirm endpoints are case-scoped (caseId in path), for example:
	•	POST /api/cases/:caseId/uploads/init
	•	POST /api/cases/:caseId/uploads/complete

	•	GET  /api/cases/:caseId/uploads/:uploadId

If your repo already has conventions, follow them, but maintain the caseId-in-path requirement. No upload endpoint may accept uploads without a caseId binding.

Storage & Ingestion
	•	Store raw objects in your existing storage layer. If S3/R2/etc: use signed URL init/complete pattern. If local dev: store under a case-scoped path.
	•	Add integrity: compute and store sha256 hash where practical.
	•	Introduce an ingestion state machine (DB column):
	•	UPLOADED → STORED → EXTRACTED → CHUNKED → INDEXED → READY
	•	and failure states: FAILED_STORING, FAILED_EXTRACTION, FAILED_CHUNKING, FAILED_INDEXING
	•	Create a background job or server-side queue mechanism if one exists; if none, implement a minimal deterministic job runner consistent with repo patterns.

Data Model Requirements (DB)

Implement or confirm tables/relations (names may differ; follow existing schema style):
	•	uploads (FK to cases)
	•	upload_pages (optional but recommended for scan mode)
	•	chunks (FK to case + upload; includes pageNumber, chunkIndex)
	•	Ensure indexes:
	•	uploads(caseId, createdAt)
	•	chunks(caseId, uploadId)
	•	Verify constraints: no orphan records; enforce cascades carefully (prefer archive/soft delete over hard delete).
