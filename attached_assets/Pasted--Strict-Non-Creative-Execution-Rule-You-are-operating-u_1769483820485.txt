# v1.23 — Public Review: Immutable Bundle Download Link (Read-only)

## 0) Goal (scope-locked)

Add a public, read-only route that allows an auditor to download a deterministic corpus bundle ZIP **by corpusId**, without auth, when `public_readonly=true`.

No writes. No bundle mutation. Use existing export logic.

---

## 1) Server endpoint

Add unauthenticated GET endpoint (only allowed when public_readonly=true):

`GET /api/review/:corpusId/bundle?deterministic=true`

Behavior:

* If `public_readonly=false`: return 401 AUTH_ERROR (same as existing unauthenticated failure)
* If `public_readonly=true`:

  * Return the same ZIP bytes as `GET /api/corpus/:corpusId/export_bundle?deterministic=true`
  * Content-Type: `application/zip`
  * Content-Disposition filename: `lantern-corpus-<corpusId>.zip`

No query options besides `deterministic=true` (required). If missing or false, 400 with:

```json
{ "type": "VALIDATION_ERROR", "message": "deterministic=true required" }
```

---

## 2) Client route (read-only)

Add a public review page:

`/review/:corpusId/bundle`

Page shows:

* Title: `Download Corpus Bundle`
* Corpus ID displayed
* One button: `Download Deterministic Bundle (ZIP)`

Button links to:
`/api/review/:corpusId/bundle?deterministic=true`

No auth header required. No token storage. No other UI.

---

## 3) Acceptance tests

1. With `public_readonly=true`, unauthenticated GET to `/api/review/:corpusId/bundle?deterministic=true` returns 200 ZIP with correct filename.
2. With `public_readonly=false`, same request returns 401 AUTH_ERROR JSON.
3. Missing deterministic=true returns 400 VALIDATION_ERROR with exact message.
4. `/review/:corpusId/bundle` page loads without auth and download works.
