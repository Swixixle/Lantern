Understood. You already have Lantern Core (claim-focused, highlight-to-receipt, JSON/PDF export). The clean next step is a sibling module that is not “claims,” but still follows the same interaction pattern: paste → extract → curate → export.

Proposed module: Lantern Extract ( /extract )

A general-purpose extraction module that outputs structured artifacts other than claims—useful for building datasets, timelines, entity maps, and quote banks from the same raw source text.

What it extracts (v1 scope)

From pasted article text + metadata, it produces an Extraction Pack with these item types:
	1.	Entities

	•	People, organizations, locations
	•	Optional normalization fields (display name, canonical guess)
	•	First-seen snippet + character offsets

	2.	Key Quotes

	•	Direct quotations and attributed statements
	•	Speaker (if inferable), quote text, surrounding context

	3.	Numbers & Metrics

	•	Counts, percentages, dollar amounts, dates/times
	•	Value + unit + sentence context

	4.	Timeline Candidates

	•	Date/time references paired with described events
	•	Outputs: date, event summary, source sentence

This is intentionally “dataset-y,” not verdict-y. Lantern Core validates a claim; Lantern Extract structures the source.

API surface (minimal, consistent with Core)

Endpoints
	1.	POST /api/extract

	•	Input: { source, text, options }
	•	Output: Extraction Pack JSON (no PDF yet)

	2.	POST /api/extract/export/pdf

	•	Input: { pack }
	•	Output: PDF bytes (visual pack)

	3.	POST /api/extract/export/json

	•	Input: { pack }
	•	Output: JSON file (download)

	4.	Optional: POST /api/extract/export/csv

	•	Output: zipped CSV bundle

Options (v1)
	•	modes: entities | quotes | metrics | timeline
	•	aggressiveness: conservative | balanced | broad
	•	max_items_per_mode
	•	require_provenance: true (default)

⸻

PDF “visual pack” format

Do not reuse the Lantern Receipt card verbatim; make it look like a binder:
	•	Cover page: Source metadata + pack_id + hashes
	•	Section dividers: Entities / Quotes / Metrics / Timeline
	•	Each item prints with:
	•	extracted content (large)
	•	provenance sentence (smaller)
	•	tags + confidence

This makes the output useful for audit trails and human review.

Acceptance criteria (what “done” means)
	1.	/extract route accessible via the same bottom-right navigation toggle.
	2.	Paste text + metadata → click “Extract” → results populate in four tabs.
	3.	User can toggle items on/off and add tags.

⸻

Primary failure mode to guard against

Extraction without reliable provenance (hallucinated entities/quotes/metrics with no exact anchor in the text).
Mitigation: enforce require_provenance=true and drop any item that cannot be traced to a substring + offsets.
