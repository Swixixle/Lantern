# Screen 5 — Snapshot & Export (v1) Implementation Contract

## 1) Purpose (scope-locked)

This screen provides:

* **Closure** (a saved, immutable “state of defensibility”)
* **Retrieval** (open an existing snapshot by ID)
* **Verification** (recompute hash and compare)
* **Export** (PDF + JSON)

It must not:

* Generate new claims
* Reclassify claims
* Recompute confidence
* Summarize the corpus
* Interpret conflicts/gaps

Screen title is fixed:

**Screen title:** `Snapshot & Export`

---

## 2) Routes

### A) Snapshot screen

`/snapshots`

### B) Snapshot detail

`/snapshots/:snapshot_id`

You already have API routes; this is UI routing only.

---

## 3) UI requirements

## A) Snapshots list screen (`/snapshots`)

Must include:

1. **Create Snapshot** section

* Button: **Save Snapshot**

  * Uses current Claim Space state (claims currently loaded in UI)
  * Calls `POST /api/snapshots`
* After success, display:

  * `snapshot_id`
  * `created_at`
  * `hash_alg`
  * `hash_hex` (full string, not truncated)
  * Button: **Open Snapshot**

2. **Open Existing Snapshot** section

* Text input: snapshot ID
* Button: **Open**

  * Navigates to `/snapshots/:snapshot_id`

No additional features.

## B) Snapshot detail screen (`/snapshots/:snapshot_id`)

Must display:

1. Header block (verbatim fields)

* snapshot_id
* created_at
* corpus_id
* hash_alg
* hash_hex (full)

2. **Verify Snapshot**

* Button: **Verify**
* Calls `GET /api/snapshots/:id/verify`
* Displays response fields:

  * verified (true/false)
  * stored_hash_hex
  * recomputed_hash_hex
* If verified = false:

  * display a neutral warning: “Verification failed: hash mismatch.”

3. **Export**

* Button: **Export JSON**

  * Downloads the full snapshot object (exact server response from `GET /api/snapshots/:id`)
  * Filename: `lantern-snapshot-<snapshot_id>.json`

* Button: **Export PDF**

  * Generates a PDF that contains only:

    * Snapshot header block (as above)
    * Claims grouped into the three sections (Defensible / Restricted / Ambiguous)
    * For each claim:

      * id
      * text
      * confidence band text
      * refusal_reason (if restricted)
      * anchor_ids list
    * Constraints summary (optional section) **ONLY if** you already have constraints for this corpus available via API.

      * If included, list constraint items by type with:

        * id
        * summary
        * anchor_ids
      * Do not expand conflicts into left/right panels in PDF (list only).
  * Filename: `lantern-snapshot-<snapshot_id>.pdf`

PDF must not include:

* Full anchor quotes (those belong in Evidence Anchors screen)
* Any narrative commentary
* Any inferred analysis

---

## 4) PDF generation constraints (v1)

* Use a straightforward, single-column layout.
* No styling beyond readable headings and line breaks.
* Ensure the PDF is deterministic in content ordering:

  * Claims sorted by `id` within each section
  * Constraint items sorted by `id` within each type (if included)

Do not add new endpoints.
