# v1.13 — Anchor Extraction Proof Mode (PDF-Grounded, Auditable)

## 0) Goal (scope-locked)

When anchors are extracted from PDFs, every anchor must be **provably grounded** in the source PDF via deterministic provenance fields.

This version provides **page-image proof** (rendered page PNG) plus a deterministic pointer to where the anchor came from on that page.

No summaries. No interpretation. No “best effort” fuzzy matching.

---

## 1) New data model (schema)

Create: `client/src/lib/schema/provenance.ts`

### A) AnchorProvenance (canonical)

```ts
export interface AnchorProvenance {
  source_sha256_hex: string;   // 64-hex, from source registry
  source_id: string;           // UUID
  page_index: number;          // 0-based
  page_ref: string;            // e.g., "p. 1" (derived from page_index + 1)
  quote_start_char: number;    // 0-based char offset in extracted page text
  quote_end_char: number;      // exclusive
  extractor: {
    name: "pdfjs-text-v1";
    version: "1.0.0";
  };
}
```

Hard rule:

* `quote_start_char` / `quote_end_char` are offsets **into the extracted page text string** produced by the extractor (see §3).
* No bounding boxes in v1.13. Only page + char-range.

### B) AnchorRecord update

Extend existing `Anchor` schema to include provenance:

```ts
export interface AnchorRecord {
  id: string;
  corpus_id: string;
  source_id: string;
  quote: string;
  source_document: string;
  page_ref: string;
  section_ref?: string | null;
  timeline_date: string;
  provenance: AnchorProvenance;
}
```

## 3) Extractor (deterministic)

### Extractor name/version

* `pdfjs-text-v1`, version `1.0.0`

### Deterministic extraction pipeline

When building anchors (in any mode that extracts from PDFs):

1. For each uploaded PDF source:
2. For each page:

   * Extract **page text** using one deterministic method (you choose implementation, but output must be stable for same PDF and same library versions).
   * Render the page to a PNG image.
   * Store:

     * page_text
     * page_text_sha256_hex
     * page_png_path
3. Anchor extraction:

   * In v1.13, anchors are created by selecting a **sentence window** from the page_text (2–4 sentences) exactly as your earlier extraction boundary.
   * Each anchor must record:

     * page_index
     * quote_start_char / quote_end_char locating the quote within page_text
     * source_sha256_hex copied from the source registry row

Hard rules:

* The `quote` string must equal `page_text.slice(quote_start_char, quote_end_char)` exactly.
* If the quote cannot be found exactly, do not create the anchor (fail the build).

## 4) API endpoints

### A) Get PDF page proof (image + text hash)

`GET /api/sources/:source_id/pages/:page_index`

Response:

```json
{
  "source_id": "uuid",
  "page_index": 0,
  "page_text_sha256_hex": "64-hex",
  "page_png_url": "/uploads/pages/<file>.png"
}
```

No page_text returned by default.

Optional query param:

* `include_text=true` (default false)

If include_text=true:

```json
{
  "source_id": "...",
  "page_index": 0,
  "page_text_sha256_hex": "...",
  "page_png_url": "...",
  "page_text": "..."
}
```

### B) Get anchor proof packet (single anchor)

`GET /api/anchors/:anchor_id/proof`

Response:

```json
{
  "anchor": { /* AnchorRecord */ },
  "page": {
    "source_id": "uuid",
    "page_index": 0,
    "page_text_sha256_hex": "64-hex",
    "page_png_url": "/uploads/pages/<file>.png"
  },
  "repro": {
    "page_text_substring": "exact substring from page_text using offsets",
    "substring_sha256_hex": "64-hex"
  }
}
```

Rules:

* `repro.page_text_substring` must equal anchor.quote exactly.
* `substring_sha256_hex` is sha256 of that substring UTF-8.

### C) Build endpoint output update

Wherever you return build results (anchors_only mode already exists), add:

* `pages_indexed`: number of pages processed
* `pages_rendered`: number of PNG pages rendered

Example:

```json
{
  "corpus_id": "...",
  "mode": "anchors_only",
  "status": "COMPLETED",
  "pages_indexed": 12,
  "pages_rendered": 12,
  "anchors_created": 7,
  "claims_created": 0,
  "constraints_created": 0
}
```

## 7) Acceptance tests

1. Build indexes pages and renders PNGs; response includes pages_indexed and pages_rendered.
2. `GET /api/sources/:source_id/pages/:page_index` returns page_text_sha256_hex and a valid png url.
3. `GET /api/anchors/:anchor_id/proof` returns anchor + page + repro where:

   * repro.page_text_substring === anchor.quote
   * substring_sha256_hex matches computed sha256 of anchor.quote
4. Anchor provenance:

   * provenance.source_sha256_hex matches the source registry sha256_hex
   * page_ref matches page_index+1 formatting
5. Bundle export includes `pages/<source_id>/page-<n>.png` and `page-<n>.json`, and their hashes appear in MANIFEST.json.
6. Deterministic behavior:

   * Re-running build on same PDFs without changes produces the same `page_text_sha256_hex` for each page.
   * Proof endpoint returns consistent offsets and quote.
