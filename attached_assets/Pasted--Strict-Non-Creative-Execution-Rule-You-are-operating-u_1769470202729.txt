# v1.3 — Anchor Browser + User-Authored Claims (No model synthesis)

## 0) Goal (scope-locked)

Allow the user to:

* Browse anchors for a corpus (filter by PRIMARY/SECONDARY)
* Select anchors
* Create a **claim draft** that is **user-entered text** and becomes:

  * DEFENSIBLE if it has ≥1 anchors
  * RESTRICTED if it has 0 anchors (with refusal_reason)
* Persist these claims per corpus
* Feed Claim Space from persisted claims (not mocks)

No AI generation of claim text. No paraphrase. No “suggested claim” features.

---

## 1) Data model additions

### A) ClaimRecord (server)

```ts
export interface ClaimRecord {
  id: string;
  corpus_id: string;
  classification: "DEFENSIBLE" | "RESTRICTED" | "AMBIGUOUS";
  text: string;
  confidence: number;              // set by rule (see below)
  refusal_reason: string | null;
  anchor_ids: string[];
  created_at: string;              // ISO
}
```

### B) Confidence rule (deterministic; no inference)

For v1.3, confidence is not “model confidence.” It is a fixed band based on anchoring:

* DEFENSIBLE (anchor_ids ≥ 1): `0.75`
* RESTRICTED (anchor_ids = 0): `0.60`
* AMBIGUOUS: `0.70` (only created explicitly via API; do not auto-create)

No other values.

---

## 2) New API endpoints (minimal set)

### A) List anchors (corpus-scoped)

`GET /api/corpus/:corpus_id/anchors`

Optional query params:

* `role=PRIMARY|SECONDARY`
* `source_id=<id>`

Response:

```json
{ "corpus_id": "uuid", "anchors": [ /* AnchorRecord[] */ ] }
```

### B) Create claim (user-authored)

`POST /api/corpus/:corpus_id/claims`

Request:

```json
{
  "text": "string (user entered)",
  "anchor_ids": ["anchor-id-1", "anchor-id-2"]
}
```

Server classification rules:

* If `anchor_ids.length >= 1`:

  * classification = DEFENSIBLE
  * confidence = 0.75
  * refusal_reason = null
* Else:

  * classification = RESTRICTED
  * confidence = 0.60
  * refusal_reason = "No anchors attached; claim is not defensible in current corpus."

Response: full ClaimRecord.

### C) List claims (corpus-scoped)

`GET /api/corpus/:corpus_id/claims`

Response:

```json
{ "corpus_id": "uuid", "claims": [ /* ClaimRecord[] */ ] }
```

### D) Delete claim (optional but recommended)

`DELETE /api/corpus/:corpus_id/claims/:claim_id`

No update endpoint in v1.3 (avoids revision complexity).

## 3) UI changes (minimal, governed)

## A) New screen: Anchor Browser

Route:
`/anchors/browse?corpusId=<id>`

Must include:

* Filters:

  * Role toggle: PRIMARY / SECONDARY / ALL
  * Source dropdown (optional if multiple sources)
* Anchor list (rows):

  * quote snippet (first N chars; verbatim)
  * source_document
  * page_ref
  * anchor id
  * checkbox to select

No ranking. Default ordering:

* by source_document then by page_ref then by id (stable sort)

## B) Claim Draft panel (on same screen)

A fixed panel with:

* Textarea: “Claim text” (user enters)
* Selected anchors list (ids only)
* Button: **Create Claim**

On submit:

* POST create claim endpoint
* On success:

  * show created claim id + classification
  * button: “Go to Claim Space”

Hard rule:

* Do not auto-fill the textarea from anchors.
* Do not offer suggested claims.

## C) Claim Space wiring (replace mocks)

Claim Space must load from:
`GET /api/corpus/:corpus_id/claims`

If none exist:

* show empty state:

  > “No claims have been created for this corpus.”
