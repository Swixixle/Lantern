# v1.9 — Authentication Gate + Upload Authorization (Minimal, Deterministic)

## 0) Goal (scope-locked)

Add a minimal authentication mechanism that:

* Gates **write** endpoints (uploads, build, create/delete claim, snapshots, packets, bundle export verify upload)
* Leaves **read-only** endpoints optionally open (configurable)
* Provides a deterministic way to test auth success/failure

No roles. No multi-user. No permissions matrix.

---

## 1) Auth mechanism (choose exactly one; implement only this)

### Option A (recommended for Replit/dev): Static API Key

* One secret value: `LANTERN_API_KEY`
* Client sends: `Authorization: Bearer <key>`
* Server validates exact match

No sessions, no cookies.

---

## 2) Required server middleware

### A) Protected routes list (exact)

Require auth for these endpoints:

* `POST /api/corpus`
* `POST /api/corpus/:corpus_id/sources`
* `POST /api/corpus/:corpus_id/build`
* `POST /api/corpus/:corpus_id/claims`
* `DELETE /api/corpus/:corpus_id/claims/:claim_id`
* `POST /api/snapshots`
* `POST /api/corpus/:corpus_id/claims/:claim_id/packet`
* `GET /api/corpus/:corpus_id/export_bundle`
* `POST /api/bundles/verify`

Everything else stays unchanged.

### B) Failure response (exact)

If missing/invalid auth:

* HTTP 401

```json
{ "type": "AUTH_ERROR", "message": "Unauthorized" }
```

No other text.

---

## 3) Auth status endpoint (for deterministic testing)

### `GET /api/auth/status`

Behavior:

* If auth valid → 200

```json
{ "authenticated": true }
```

* If auth invalid/missing → 401 (same AUTH_ERROR response)

This endpoint is protected (it exists to test the gate).

### C) UI failure behavior
