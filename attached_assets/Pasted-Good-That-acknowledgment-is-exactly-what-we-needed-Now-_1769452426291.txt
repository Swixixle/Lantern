## Step 1 — Claim Space View: Implementation Contract

### A. Data model (minimum viable)

Use this exact shape. Keep it boring and typed.

**Claim**

* `id` (string, stable UUID)
* `classification` (`"DEFENSIBLE" | "RESTRICTED" | "AMBIGUOUS"`)
* `text` (string)
* `confidence` (number; enforce `< 1.0` and `<= 0.90` for v1 unless you have a reason)
* `refusal_reason` (string | null)

  * **Required** for `RESTRICTED`
* `anchor_ids` (string[])

  * Empty allowed for `RESTRICTED` and `AMBIGUOUS`
  * **Must be non-empty** for `DEFENSIBLE`

**Confidence band display rule**

* Convert number to band text:

  * `0.60–0.69 = "60–70%"`
  * `0.70–0.79 = "70–80%"`
  * `0.80–0.89 = "80–90%"`
  * `0.90–0.99 = "90–99%"` (still not 100)
* If confidence would be `1.0`, clamp to `0.95` and log a warning.

---

### B. API contract (minimum viable)

You can hardcode data initially, but the **interface must exist**.

* `GET /api/claims?corpusId=<id>`

  * returns `{ corpusId, claims: Claim[] }`

* (Optional now, required later) `GET /api/anchors?ids=<comma-separated>`

  * returns `{ anchors: Anchor[] }`

If you already have a “Deep Read” endpoint, this Claim list can be mocked now and later derived from the extraction pipeline.

---

### C. UI behavior (must match Monday spec)

**Default landing page:** Claim Space View.

Layout requirements:

* Three sections with headings exactly:

  1. **Defensible Claims**
  2. **Restricted / Unsupported Claims**
  3. **Ambiguous Claims**

Each claim row/card must show:

* Claim text
* Confidence band (not raw decimals)
* Button: **View Evidence**

**View Evidence button logic**

* If `classification = DEFENSIBLE` and `anchor_ids.length > 0` → navigate to Anchor View with those ids
* Otherwise (Restricted/Ambiguous with no anchors) → still open Anchor View but show:

  * “No anchors available for this claim in the current corpus.”

**Restricted claims: refusal language**
Every Restricted claim must include:

* A visible refusal label (e.g., “Not supported by corpus”)
* `refusal_reason` rendered verbatim (1–2 lines)

Hard rule:

* No summaries
* No inferred policy intent
* No rankings
* No “insights”
