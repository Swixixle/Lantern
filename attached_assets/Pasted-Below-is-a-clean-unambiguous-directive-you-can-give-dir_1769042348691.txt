Objective

⸻

PART 1 — “HOW LANTERN WORKS” REFERENCE PANEL

Placement
	•	Add a hamburger menu (☰) item labeled “How Lantern Works”
	•	This must not appear in the primary workflow, editor, or report surface
	•	It must be accessible but optional

⸻

Nature of the Content

This section is a reference manual, not onboarding.

It must:
	•	Explain method, limits, and safeguards
	•	Reduce misinterpretation
	•	Teach restraint, not capability

It must not:
	•	Guide users toward conclusions
	•	Encourage analysis
	•	Simplify or gamify
	•	Introduce step-by-step “success paths”

Think: laboratory manual, legal appendix, instrument documentation.

⸻

Required Sections (Exact)

1. What Lantern Is (and Is Not)
	•	Declarative statements only
	•	Explicitly state:
	•	Lantern records claims and evidence
	•	Lantern applies bounded heuristics
	•	Lantern does not determine truth, intent, or guilt
	•	Lantern may refuse analysis when evidence is insufficient

2. Core Concepts
Define clearly and minimally:
	•	Extract Pack
	•	Dossier
	•	Entity
	•	Claim
	•	Claim Scope (Utterance vs Content)
	•	Evidence
	•	Heuristic

No metaphors. No examples beyond one sentence if needed.

3. Heuristics (With Limits)
For each heuristic:
	•	Influence Hubs
	•	Funding Gravity
	•	Enforcement Map
	•	Sensitivity / Robustness

Each must include:
	•	What it measures
	•	What it explicitly does not imply

4. Limits & Safeguards
Explain:
	•	Evidence density thresholds
	•	“Insufficient Data” gating
	•	Migration logs
	•	Sensitivity checks
	•	Comparison sufficiency rules
	•	Cryptographic fingerprints

Emphasize that refusal is correct behavior.

5. Responsible Use
State plainly:
	•	Lantern is an evidentiary record, not an accusation engine
	•	Outputs require interpretation under scrutiny
	•	Misuse is outside system intent

⸻

Visual / UX Constraints
	•	Neutral styling only
	•	No animations
	•	No progress indicators
	•	No calls to action
	•	Scroll-based reading is acceptable
	•	This panel should feel boring on purpose

PART 2 — REQUIRED SYSTEM MAP (MANDATORY)

In addition to implementing the UI reference panel, the agent must produce a written system map delivered as a document or markdown file.

B. Data Lifecycle
	•	Extract → Dossier → Analysis → Report → Export

	•	Where integrity checks occur
	•	Where refusal / gating occurs

C. Schema & Versioning
	•	All pack types
	•	Discriminators used
	•	Migration strategy

D. Heuristic Pipeline
For each heuristic:
	•	Inputs
	•	Thresholds
	•	Outputs
	•	Failure modes

E. Integrity & Safety Layers
	•	Report fingerprinting
	•	Comparison fingerprinting
	•	Migration logs
	•	Sensitivity analysis

F. UX Boundaries
Explicitly list:
	•	What users can do
	•	What users cannot do
	•	Where Lantern refuses action

⸻

Output Requirements for the Map

	•	No marketing tone
