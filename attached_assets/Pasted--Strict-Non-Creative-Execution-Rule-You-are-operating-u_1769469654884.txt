# v1.2 — Extraction Pipeline Boundaries (No-Creative, No-Assumptions)

## 0) Goal (scope-locked)

Introduce a **mechanical** pipeline that produces:

* Anchors (verbatim quotes + citations)
* Claims (only if anchored)
* Constraints (only if anchored or explicitly “missing evidence”)

This does **not** introduce:

* Summaries
* Doctrine synthesis
* Ranking
* Intent inference
* “Insights”

---

## 1) New endpoint: Build corpus artifacts (explicit, user-triggered)

Add exactly one new endpoint:

### `POST /api/corpus/:corpus_id/build`

Request:

```json
{ "mode": "anchors_only" }
```

Allowed modes (enum):

* `"anchors_only"` (v1.2 default)
* `"claims_from_anchors"` (v1.2 optional; may be stubbed)

Response:

```json
{
  "corpus_id": "uuid",
  "mode": "anchors_only",
  "status": "COMPLETED",
  "anchors_created": 12,
  "claims_created": 0,
  "constraints_created": 0
}
```

Hard rules:

* Build is never automatic on upload.
* Build must be explicitly triggered by user action.

---

## 2) Anchors extraction (v1.2 minimum)

### A) What qualifies as an anchor

An Anchor is an extracted passage that is:

* Verbatim text from a source
* Bounded by a deterministic extraction rule
* Cited to source document + page/section

### B) Deterministic extraction rule (no creative liberty)

Implement one of these, choose exactly one and document which you chose:

**Rule Option 1 (PDF text segmentation):**

* Split text by headings and paragraphs.
* Create anchors for paragraphs under a max length (e.g., 400–800 chars).
* Preserve exact text.

**Rule Option 2 (Sentence-window):**

* Split into sentences.
* Create anchors in fixed windows (e.g., 2–4 sentences).
* Preserve exact text.

No “importance” scoring. No relevance inference.

### C) Anchor schema update (server)

Bind anchors to corpus + source:

```ts
export interface AnchorRecord {
  id: string;
  corpus_id: string;
  source_id: string;
  quote: string;
  source_document: string;
  page_ref: string;
  section_ref?: string | null;
  timeline_date: string;
}
```

Hard rule:

* `source_document` must equal the stored filename from CorpusSource.
* `timeline_date` must be derived from an explicit date in the document metadata **or** the upload timestamp. Choose one, document it, and do not infer dates from content unless explicitly present (v1.2 default: use upload date).

## 3) Claims generation boundary (v1.2 default = OFF)

In v1.2, claim generation remains mocked unless you implement the following strict rule set.

### Allowed claim generation rule set (if implemented)

A claim may be created only if:

* It is a literal restatement of an anchor’s text at a higher abstraction level **without adding any new facts**.

This is difficult to guarantee automatically. Therefore:

**Default for v1.2:** `mode="anchors_only"` and `claims_created=0`.

---

## 4) Constraints generation boundary (v1.2 default = OFF)

Default OFF.

If implemented later:

* CONFLICT requires two anchors with directly contradictory literals (same field differing values).
* TIME_MISMATCH requires explicit dates, not inferred.
* MISSING_EVIDENCE may be user-entered only (not auto-generated) in v1.2.
