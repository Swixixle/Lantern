v1.10 is **accepted as complete** with one **explicit spec deviation** that you correctly identified and must now resolve to satisfy v1.10 Acceptance Test #4 (“deterministic across multiple exports when corpus unchanged and same params used”).

### The deviation

* In v1.7, `MANIFEST.json` includes `generated_at`.
* v1.7 hashing explicitly excludes `generated_at`, so **manifest_hash_hex is deterministic**, but the **ZIP bytes can still differ** because the file contents differ.
* v1.10 requires the *repro pack* to be deterministic across exports. If the inner bundle ZIP differs bytewise, then the repro pack cannot be bytewise deterministic because `bundle/*.zip` hash changes.

This is not a “maybe.” It’s a direct consequence of including a timestamp field in a file whose bytes are hashed into the outer pack.

# v1.10.1 — Deterministic Inner Bundle for Repro Pack (Patch Contract)

## 0) Goal (scope-locked)

Make the repro pack deterministic by ensuring the embedded corpus bundle ZIP is deterministic **byte-for-byte** when:

* corpus unchanged
* same params used
* same code version

Do not change any other behavior.

---

## 1) Change (exact)

Modify v1.7 bundle export logic to support a deterministic mode used **only** by v1.10 repro pack endpoint.

### A) Add a query param to v1.7 exporter

`GET /api/corpus/:corpus_id/export_bundle`

Add optional query param:

* `deterministic=true|false` (default false)

### B) When deterministic=true

In the inner bundle’s `MANIFEST.json`:

* Set `generated_at` to the exact constant string:
  `"1970-01-01T00:00:00.000Z"`

Do not remove the field. Do not rename it. Do not omit it. Only set to constant.

Everything else unchanged.

Rationale: this preserves the v1.7 schema exactly while making file bytes stable.

---

## 2) v1.10 repro pack endpoint change (exact)

When generating the embedded bundle, call v1.7 bundle generator with:

* `deterministic=true`
* `include_raw_sources=<as requested>`

Do not modify the verifier logic.

---

## 3) Acceptance tests (must pass)

1. Export repro pack twice with same params, unchanged corpus → **outer ZIP bytes identical**.
2. REPRO_MANIFEST.json `hash_hex` identical across exports.
3. Inner bundle ZIP sha256 identical across exports.
4. Inner bundle manifest_hash_hex remains correct (still excluding generated_at; constant value does not break it).
5. Normal v1.7 export_bundle without deterministic=true remains unchanged (generated_at is real time).
