Immediate next iteration (v0.1.3) — focus on quality, not features

Now that safety is enforced, you should optimize for precision and legibility.

1) Entity quality upgrades

Problem: “Apple” vs “Apple Inc” being distinct is correct, but you need better merge/cross-link logic without collapsing distinct concepts.

Add optional linkage:
	•	canonical_family_id (e.g., a stable hash of the root token “Apple”)
	•	Keep them distinct items, but allow the UI/export to show “related entities.”

This improves downstream usefulness without breaking epistemic discipline.

2) Quote attribution hardening

Add two protections:
	•	Attribution verb must be in the same or adjacent sentence as the quote.
	•	If >1 candidate speaker matches, set speaker=null and record speaker_candidates[].

This prevents “clean but wrong” outputs.

3) Metrics normalization completeness

If you aren’t already:
	•	store raw_value_text, parsed_number, scale, unit, qualifier
	•	keep normalized_number null when ambiguous

Your metrics stream should be your highest-precision stream. Treat it like a reference-grade parser.

4) Timeline ambiguity policy

Make an explicit rule:
	•	partial/relative dates never normalize
	•	store date_type (explicit|partial|relative|year-only)
	•	store raw_date_text always

This keeps timeline outputs honest and makes packs safe for downstream automation.

Now: should you “upgrade to full-stack” for persistence?

You are closer, but I would still sequence it carefully.

The right time to add persistence is when:
	•	fixtures cover at least ~15–20 texts
	•	you’ve stabilized behavior across all three modes for those fixtures
	•	you want reproducible pack comparison across engine versions

If those are true, you can add a minimal persistence slice safely:
	•	Store curated packs (JSON) + hashes + engine version
	•	Retrieve by pack_id/source_url
	•	SQLite is fine

Do not build dashboards or analytics yet.
