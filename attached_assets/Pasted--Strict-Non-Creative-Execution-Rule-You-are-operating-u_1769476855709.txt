# v1.14 — anchors_proof_index.json in Exports (Deterministic)

## 0) Goal (scope-locked)

Add a single deterministic index file to the v1.7 corpus bundle export that enables third-party audit tooling to verify anchor provenance **without calling APIs**.

No new inference. No new content beyond existing stored fields.

---

## 1) Bundle structure change (v1.7)

Add file at bundle root:
`anchors_proof_index.json`

Bundle layout now includes:

```
anchors_proof_index.json
pages/<source_id>/page-<page_index>.png
pages/<source_id>/page-<page_index>.json
...
```

`anchors_proof_index.json` must be included in MANIFEST.json `files[]` with sha256 like all other files.

---

## 2) File format (exact)

### anchors_proof_index.json

```json
{
  "corpus_id": "uuid",
  "extractor": { "name": "pdfjs-text-v1", "version": "1.0.0" },
  "anchors": [
    {
      "anchor_id": "uuid",
      "source_id": "uuid",
      "page_index": 0,
      "quote_start_char": 0,
      "quote_end_char": 63,
      "page_text_sha256_hex": "64-hex"
    }
  ]
}
```

Hard rules:

* `anchors[]` must include **every anchor** in the corpus that has `provenance.extractor.name === "pdfjs-text-v1"`.
* Each anchor entry fields must be copied from stored anchor provenance and page table:

  * `page_text_sha256_hex` comes from `pdf_pages.page_text_sha256_hex` for `(source_id, page_index)`
* No `quote` field. No `source_sha256_hex`. No filenames. Only the exact fields above.
* `anchors[]` must be sorted lexicographically by `anchor_id` (string compare).
* Top-level keys must appear in this order:

  1. `corpus_id`
  2. `extractor`
  3. `anchors`

## 3) Determinism requirements

  * no pretty-print requirement (you may minify or indent, but must be consistent every time). Choose one and keep it fixed.
