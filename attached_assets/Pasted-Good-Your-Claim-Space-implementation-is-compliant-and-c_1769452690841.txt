# 2) Snapshot + Hash Specification (v1)

This is the core defensibility artifact. The goal is:

* Immutable snapshot ID
* Re-verifiable by hash
* Reproducible hash via canonical serialization

## A. Snapshot schema (server-side strongly preferred)

Create a server-side snapshot model:

```ts
export interface Snapshot {
  snapshot_id: string;          // UUID
  created_at: string;           // ISO datetime
  corpus_id: string;            // string
  claims: {
    id: string;
    classification: "DEFENSIBLE" | "RESTRICTED" | "AMBIGUOUS";
    text: string;
    confidence: number;         // stored numeric
    refusal_reason: string | null;
    anchor_ids: string[];
  }[];
  hash_alg: "SHA-256";
  hash_hex: string;             // computed over canonical payload
}
```

Hard rule:

* Snapshot must store **exactly what was shown** in Claim Space at save-time.

## B. Canonical hashing rule (do this exactly)

### Canonical payload

Compute the hash over a canonical JSON payload that excludes mutable metadata:

* Include: `corpus_id`, `claims` (full), and nothing else.
* Exclude: `snapshot_id`, `created_at`, `hash_*`.

### Canonicalization steps

1. Sort claims by `id` ascending
2. Within each claim, sort `anchor_ids` ascending
3. Serialize using stable JSON stringify (no whitespace variability)

### Hash algorithm

SHA-256 of UTF-8 bytes of canonical JSON string.

### Node example (server)

```ts
import crypto from "crypto";

function canonicalizeForHash(corpus_id: string, claims: Snapshot["claims"]) {
  const sortedClaims = [...claims].map(c => ({
    ...c,
    anchor_ids: [...c.anchor_ids].sort(),
  })).sort((a, b) => a.id.localeCompare(b.id));

  return JSON.stringify({ corpus_id, claims: sortedClaims });
}

export function computeSnapshotHash(corpus_id: string, claims: Snapshot["claims"]) {
  const canonical = canonicalizeForHash(corpus_id, claims);
  return crypto.createHash("sha256").update(canonical, "utf8").digest("hex");
}
```

```json
}
```

If mismatch:

* `verified: false`
* include both hashes
