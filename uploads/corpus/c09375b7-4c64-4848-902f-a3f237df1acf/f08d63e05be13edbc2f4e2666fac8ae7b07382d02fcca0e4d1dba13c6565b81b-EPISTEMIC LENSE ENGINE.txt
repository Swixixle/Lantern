0) One-sentence definition

LENSES is a deterministic, hash-chained, human-gated extraction and reasoning control plane that converts unstructured text into an auditable record of primitives and (optionally) derived claims—then stress-tests itself for fragility, drift, and governance failures.

⸻

1) Core Concepts (non-negotiable)

1.1 ExtractionPack is the “ledger”

All work happens on an immutable ExtractionPack that carries:
	•	docs (raw + segmented text)
	•	items (extracted primitives + derived claims)
	•	flags (global safety + governance state)
	•	lensLog (append-only execution history)
	•	stable hashes for integrity verification

1.2 Lenses are pure functions with audit logs

A Lens is a single step that:
	•	accepts a pack
	•	returns a new pack revision (never mutates)
	•	appends a LensLogEntry that includes:
	•	input hash(es)
	•	output hash
	•	refusal state + reason
	•	metrics (counts, thresholds, etc.)

1.3 “Refusal is success”

A refused lens run must still:
	•	create a new revision
	•	hash-chain into the history
	•	record the refusal reason
This prevents silent failure and preserves audit continuity.

1.4 Identity Stability is sacred

Each ExtractedItem.itemId must be deterministic and collision-resistant:
	•	MUST include type, normalizedValue/value, docId, segId, charStart, charEnd
	•	Any “same itemId, different semantic signature” is CRITICAL IDENTITY DRIFT

1.5 Claims are not allowed without explicit human opt-in

Derived objects (claims) are privileged. They require:
	•	manifest opt-in (human_control.opt_in_required: true)
	•	a pack-level explicit opt-in flag set by UI/policy
	•	gate conditions satisfied (bias + evidence grade)

Invariant: inv.no_claims_without_opt_in must be enforced at runtime and by harness.

2) What this system ships (v1.1 scope)

2.1 The Precision Extraction Stack (6 lenses)
	1.	core.segment_anchor.v1
Deterministic segmentation with stable spans.
	2.	core.typed_extract.v1
LLM-assisted extraction of primitives (entity/quote/metric/event/definition) with strict schema and anchor offset validation.
	3.	core.canonicalize_dedupe.v1
Deterministic canonicalization + cluster assignment (no LLM).
	4.	core.evidence_grade.v1
Deterministic grading of item confidence bands (no LLM).
	5.	diagnostic.bias_coverage.v1
Deterministic detection of low-context + single-source + segment concentration.
	6.	core.precision_claims.v1
Constructive lens (derived claims), heavily gated, opt-in required, “clerk mode,” provenance required.

2.2 The Epistemic Stress Harness

A wind-tunnel that does not “judge truth,” but tests:
	•	stability under perturbations
	•	gating behavior
	•	refusal behavior
	•	drift/collision detection
	•	“system breaks where” fragility mapping

2.3 Visibility Layer (Developer UI)
	•	Timeline: shows lens execution chain and refusal/gate events
	•	Provenance drilldown: highlights evidence spans in segment text
	•	Compare: stable diffs between two pack revisions
	•	Seed: scenario seeding for deterministic demos
	•	Fragility Map: scenario x invariant matrix with CRITICAL alerts

2.4 Storage Layer

Local persistence of:
	•	HEAD pointer per packId
	•	snapshots keyed by revisionId
	•	an index list (timestamp, label, itemCount)
Storage is structured to support timeline browsing and revision compare.

5) Hashing & Canonicalization (Phase 1 foundation)

5.1 Deterministic itemId

itemId = sha256(type | normalizedOrValue | docId | segId | charStart-charEnd)

5.2 Pack hash

computePackHash(pack) must hash canonicalized content, excluding:
	•	revisionId
	•	LensLogEntry.startedAt/endedAt
	•	any timestamps not part of semantic content

Canonicalization MUST:
	•	sort docs deterministically
	•	sort segments deterministically by span
	•	sort items by itemId
	•	sort each item’s anchors by docId:segId:charStart:charEnd
	•	include type, status, confidence score + band, normalized value/value, flags, anchor keys

5.3 Identity Drift Detector (always-on)

Define:
	•	itemSignature(item) = canonical JSON string of:
	•	type
	•	normalizedValue/value
	•	status
	•	confidence.band + score
	•	anchor span keys
	•	relevant attributes for type (e.g., metric number/unit, entityType)
	•	detectIdentityDrift(packs):
	•	if same itemId maps to different itemSignature across revisions → CRITICAL

This is used in:
	•	Compare UI
	•	Harness invariants
	•	optional runtime guardrails in dev builds

7) Lens Requirements (6-lens suite)

Lens 1 — core.segment_anchor.v1

Deterministic segmentation with optional overlap to prevent boundary loss.

Rules:
	•	segId format: ${docId}:${charStart}-${charEnd}
	•	stable segmentation strategy (paragraph-first + sentence packing)
	•	constants:
	•	TARGET_SEGMENT_CHARS (e.g., 900–1400)
	•	MIN_SEGMENT_CHARS (merge small tails)
	•	OVERLAP_CHARS (e.g., 60) to protect against split entities/metrics

Refusal:
	•	if rawText is too short or empty → refusal revision with reason

Outputs:
	•	SourceDoc.segments created/updated only via new pack revision

Lens 2 — core.typed_extract.v1 (Gemini)

LLM-assisted extraction of primitives. Must be schema-strict and discard-first.

Allowed types:
	•	entity, quote, metric, event, definition
Forbidden:
	•	claims, hypotheses, synthesis, external sources, long prose

Hard firewall:
	•	parse Gemini JSON with Zod PrimitiveSchema.safeParse
	•	discard invalid objects
	•	discard items without exact offsets
	•	discard items whose offsets do not match text (“offset-value firewall”)

Offset-value firewall:
	•	actual = segment.text.slice(charStart, charEnd)
	•	if type === quote: require actual === value
	•	else: require actual.includes(value) (or stricter rule per type)
	•	if fail → discard

Anchor translation:
	•	globalCharStart = segment.charStart + localCharStart
	•	globalCharEnd = segment.charStart + localCharEnd

Confidence on creation:
	•	default to MED with rationale LLM_STRICT_EXTRACT
	•	status default PROPOSED

Lens 3 — core.canonicalize_dedupe.v1

Pure deterministic normalization + clustering.

Requirements:
	•	compute normalizedValue (e.g., trim, collapse spaces, canonical case)
	•	metrics: normalize currency/unit tokens
	•	set attributes.clusterId = sha256(type|normalizedValue)
	•	set attributes.clusterMembers optional
	•	dedupe behavior must be additive (never remove original anchors)

Refusal:
	•	if item_count < threshold specified in manifest → refusal revision

Lens 4 — core.evidence_grade.v1

Pure deterministic grading.

Inputs:
	•	items + their flags + cluster info

Heuristics:
	•	consensus bonus if cluster has multiple members
	•	multi-segment bonus if item has anchors in multiple segments
	•	penalties:
	•	low_context (heavy)
	•	single_source (moderate)
	•	deterministic band thresholds (no floating jitter)
	•	set confidence rationale string describing applied heuristics

Refusal:
	•	if no items → refusal revision

Lens 5 — diagnostic.bias_coverage.v1

Pure deterministic.

Must set:
	•	per-item flags and tags:
	•	low_context, single_source
	•	pack-level flag:
	•	bias_flagged_critical

Critical bias rule:
	•	if top segments cover >=80% of anchors while those segments are <=10% of total segments → critical

Refusal:
	•	if no segments → refusal revision

Lens 6 — core.precision_claims.v1

Constructive + opt-in required.

Gates:
	•	refuses if pack.flags.bias_flagged_critical === true
	•	refuses if no HIGH confidence primitives exist
	•	refuses if pack.flags.__claims_opt_in !== true (or policy overlay denies)

Claim construction rules:
	•	claims must be derived restatements only, not new conclusions
	•	claims must include provenance:
	•	attributes.supportingItemIds: string[]
	•	anchors must be sourced from supporting items’ anchors
	•	claims default status PROPOSED
	•	confidence band should not exceed evidence band of supports

LENSES

A System for Verifiable Intelligence in an AI World

The Problem We’re Solving

AI systems are becoming fluent, persuasive, and fast—but not accountable.

Today’s tools can:
	•	summarize documents,
	•	extract insights,
	•	generate confident conclusions,

…but they cannot reliably explain how they arrived there, why they should be trusted, or when they should stay silent.

This creates three systemic failures:
	1.	Hallucination Risk
Outputs sound authoritative but cannot be traced back to exact source evidence.
	2.	Confidence Without Conditions
AI speaks even when the evidence is weak, biased, or incomplete.
	3.	No Governance Layer
There is no reliable way to say “this system should not be allowed to make claims under these conditions.”

As AI is increasingly used in research, finance, policy, law, healthcare, and intelligence analysis, these failures are no longer acceptable.

⸻

The Core Idea

LENSES is not an AI that answers questions.
It is a control plane that governs how intelligence is extracted, validated, constrained, and authorized.

Think of it as:

A black box flight recorder for AI reasoning.

Instead of asking:

“Is this output correct?”

LENSES asks:

“Under what conditions is this output allowed to exist at all?”

⸻

How LENSES Works (Conceptually)

LENSES processes information through a sequence of independent analytical layers called “lenses.”

Each lens performs one bounded function, such as:
	•	segmenting text,
	•	extracting facts,
	•	checking bias,
	•	grading evidence strength,
	•	or (optionally) constructing claims.

Each step:
	•	produces a new immutable record,
	•	is cryptographically linked to the previous step,
	•	and can refuse to proceed if safety or quality conditions are violated.

Refusal is not failure.
Refusal is governance working as intended.

⸻

The Key Innovation: Evidence Before Intelligence

Most AI systems optimize for answers.
LENSES optimizes for evidence integrity.

Every extracted fact must:
	•	point to a precise location in the original source text,
	•	survive bias and coverage diagnostics,
	•	maintain stable identity across reruns,
	•	and pass deterministic grading rules.

If these conditions are not met:
	•	the system downgrades confidence, or
	•	blocks higher-level reasoning entirely.

This creates a ladder of evidence:
Text → Fact → Confidence → Claim
Each rung is optional, gated, and auditable.

⸻

Human Authority Is Explicit, Not Implied

In LENSES, claims cannot appear accidentally.

Even if the system is confident:
	•	a human must explicitly authorize the system to produce claims,
	•	and that authorization is recorded as part of the audit trail.

This turns AI from:

“an autonomous narrator”

into:

“a constrained researcher that must ask permission to speak.”

⸻

Stress-Testing the System Itself

LENSES includes an Epistemic Stress Harness—a built-in adversarial testing environment.

Instead of checking “accuracy” against external truth (often unavailable), it measures:
	•	stability under perturbation,
	•	whether safety gates trigger when they should,
	•	whether identity or provenance breaks under pressure,
	•	and whether the system becomes overconfident in fragile conditions.

This answers a more important question:

“Where does this system break, and how gracefully?”

Few AI products test this.
Almost none expose it to users.

⸻

What Makes This Different

LENSES is not:
	•	another chatbot,
	•	another summarizer,
	•	another RAG pipeline,
	•	or another scoring model.

It is:
	•	deterministic where possible,
	•	probabilistic only where unavoidable,
	•	auditable end-to-end,
	•	and designed to fail closed, not loudly.

Most systems hide uncertainty.
LENSES surfaces it as a first-class product feature.

Who This Is For

LENSES is designed for environments where being wrong confidently is worse than saying nothing:
	•	Research organizations
	•	Intelligence and risk analysis teams
	•	Legal and compliance groups
	•	Financial due diligence
	•	Policy analysis
	•	Medical literature synthesis
	•	AI governance and safety teams
	•	Any organization deploying AI where trust must be earned, not assumed

Why This Is Valuable

LENSES does not just produce outputs—it produces defensible decisions.

It allows organizations to say:
	•	“Here is exactly what we know.”
	•	“Here is where the evidence is weak.”
	•	“Here is why the system refused to speculate.”
	•	“Here is the audit trail showing how this conclusion was authorized.”

In a world moving toward AI regulation, litigation, and accountability, this is not optional infrastructure—it is inevitable infrastructure.

LENSES is built on the belief that:

The future belongs to systems that know when not to speak.
