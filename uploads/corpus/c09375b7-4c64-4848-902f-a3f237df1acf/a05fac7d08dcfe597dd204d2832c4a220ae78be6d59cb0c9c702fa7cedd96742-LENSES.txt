1. What a lens is (formal definition)

A lens is not analysis.

A lens is:

A constrained transformation of an existing record, with explicit scope, refusal rules, and non-authority guarantees.

Formally, every lens should declare:
	•	Input contract – what data it is allowed to see
	•	Operation type – classify / transform / test / simulate (never “opine”)
	•	Output shape – additive, annotative, or veto-only
	•	Refusal conditions – when it must not run
	•	Authority limit – what it is not allowed to conclude

If a “lens” cannot state those five things, it’s not a lens — it’s a blob of reasoning.

⸻

2. Three lens classes (this is critical)

To prevent drift and hallucinated authority, lenses must belong to one class only.

Class I — Structural Lenses (SAFE, foundational)

Operate only on what exists.
	•	No interpretation
	•	No external knowledge
	•	No synthesis across records

Examples:
	•	Entity normalization
	•	Metric extraction
	•	Timeline ordering
	•	Deduplication
	•	Confidence scoring

You already have these. These are substrate lenses.

⸻

Class II — Diagnostic Lenses (CONDITIONAL)

Ask: Is the record sufficient / biased / fragile?

They do not add claims. They add warnings, flags, or classifications.

Examples:
	•	Bias lens
	•	Coverage gap lens
	•	Sensitivity / robustness lens
	•	Conflict detection lens

These are allowed to say:

“This is weak / incomplete / unstable.”

They are not allowed to say:

“Therefore X is true.”

⸻

Class III — Constructive Lenses (DANGEROUS, gated)

These create new objects:
	•	hypotheses
	•	summaries
	•	inferred relations
	•	synthesized narratives

These must always:
	•	be opt-in
	•	be explicitly labeled as derived
	•	be removable without damaging the base record

This is where most AI systems collapse.
You’re right to treat this as later-stage.

⸻

Lens 1 — Bias & Coverage Lens (Diagnostic)

Purpose: Detect asymmetries and absences.
	•	Inputs:
	•	entities
	•	quotes
	•	source metadata
	•	Outputs:
	•	flags like:
	•	“Single-source dominance”
	•	“Metric-heavy, entity-light”
	•	“No opposing claims detected”
	•	Refusal:
	•	< N entities or quotes
	•	Authority limit:
	•	Cannot declare bias intent
	•	Cannot rewrite content

This lens does not judge truth — it judges shape.

⸻

Lens 2 — Robustness / Sensitivity Lens (Diagnostic)

You already have the beginnings of this.
	•	Inputs:
	•	extracted structures
	•	Operation:
	•	simulate removal of items
	•	Outputs:
	•	ROBUST / FRAGILE / SINGLE-POINT
	•	Authority limit:
	•	Cannot rank importance
	•	Cannot add facts

This lens tells you how breakable the picture is.

⸻

Lens 3 — Inference Lens (Constructive, gated)

This is where you must be extremely strict.

Rename it to avoid accidental authority:

Hypothesis Lens

	•	Inputs:
	•	metrics + entities only
	•	Operation:
	•	propose candidate relations with confidence bands
	•	Outputs:
	•	objects like:

hypothesis:
  statement: "X may influence Y"
  basis: [metric A, entity B]
  confidence: LOW


	•	Required disclaimer:
	•	“Hypotheses are non-factual constructs.”
	•	Refusal:
	•	if Bias or Robustness lenses flag critical weakness

This lens should feel dangerous to use — that’s good.

⸻

Lens 4 — Synthesis Lens (Constructive, late-stage)

Only allowed when:
	•	multiple packs
	•	sufficient robustness
	•	human explicitly enables

️
	•	Inputs:
	•	multiple dossiers
	•	Output:
	•	summaries, clusters, patterns
	•	Hard rule:
	•	Synthesis never overwrites primary records

Think of this as map-making, not truth-making.

⸻

Lens 5 — Validation Lens (Diagnostic, external)

This is not fact-checking in the popular sense.
	•	Inputs:
	•	claims / hypotheses
	•	Operation:
	•	cross-reference with external corpora or models
	•	Outputs:
	•	alignment / contradiction / unknown
	•	Authority limit:
	•	No adjudication of correctness

This lens says:

“Other systems say X / Y / nothing.”

Not:

“Therefore X is correct.”

⸻

4. How lenses stack without corruption

This is the rule that saves you:

No lens may consume its own output class.

Translated:
	•	Structural lenses cannot read Constructive outputs
	•	Diagnostic lenses cannot depend on Hypotheses
	•	Constructive lenses must declare which diagnostics gate them

Visually:

Raw Text
   ↓
[Structural Lenses]
   ↓
[Diagnostic Lenses]
   ↓ (only if allowed)
[Constructive Lenses]

This makes the system composable but not self-reinforcing.

Precision Extraction Control Plane — Master Copy v1.1

This repository implements a deterministic, auditable extraction system that converts unstructured text into verifiable knowledge with cryptographic integrity and full provenance visibility.

It is not an “AI pipeline.”
It is a control plane that governs how AI is allowed to operate.

⸻

1. What This System Does

Given source text, the system:
	1.	Segments text deterministically
	2.	Extracts primitives (entities, quotes, metrics) with mandatory anchors
	3.	Canonicalizes and deduplicates surface forms
	4.	Grades evidence using structural heuristics
	5.	Diagnoses bias and coverage
	6.	Constructs claims only when allowed
	7.	Persists every step as an immutable, hash-chained revision
	8.	Visualizes the entire process in a Timeline + Compare UI

Every output can be traced back to exact character spans in the original text.

⸻

2. Core Guarantees (Non-Negotiable)

The system enforces these invariants at runtime:
	•	Immutable Revisions
No in-place mutation. Every lens produces a new ExtractionPack with a parentRevisionId.
	•	Collision-Proof Identity
itemId = sha256(type | normalizedValue | docId | segId | charStart | charEnd)
	•	Refusal Is a Valid Outcome
A refused lens still produces a revision, hash, and audit log entry.
	•	Provenance Is Ground Truth
UI highlights are derived from Segment.text via global→local coordinate mapping.

Violating any of these is a system bug, not a feature.

⸻

9. Common Failure States (By Design)

Scenario	Result
No anchors	Item discarded
Offset/value mismatch	Item discarded
Bias concentration	Claims refused
No HIGH confidence evidence	Claims refused
Manual mutation	Hash mismatch (stale pack)

These are safety features.

⸻

10. Extending the System

Safe extensions:
	•	New diagnostic lenses
	•	New UI views
	•	New storage backends
	•	Multi-document extraction

Unsafe extensions:
	•	Mutating packs in place
	•	Letting LLMs generate claims directly
	•	Skipping anchor validation
	•	Weakening identity hashing
